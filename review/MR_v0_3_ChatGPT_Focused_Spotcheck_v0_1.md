## BLOCKER B1 — N1's claimed calibrated cross-track global p-value is not generally established

**Source:** §§3.9, 5.2–5.3, 5A, 5B; MRD-17/18; PO-1/3; MRT-16; §18.4. §5A says that independently simulating each target's fair outcome while holding **all** previously recorded WF forecasts fixed provides a null distribution that automatically captures correlations among adaptive methods and measures, without refitting. This is true for certain individual statistics whose null distributions are invariant to the forecast and for a block of forecasts all fixed before the block's outcomes; it is **not true in general** for a whole sequence in which a method at target N depends on outcomes before N. By the end of the window, the observed *future* forecast vectors contain information about *earlier* observed outcomes. Fixing all forecast vectors and replacing all outcomes destroys that feedback relationship.

**Exact exhaustive counterexample, with NO lottery outcomes or project data:** Consider four independent fair binary outcomes. Method A predicts 0 every time. Method B predicts 0 on the first draw and thereafter predicts the preceding observed outcome (perfectly legitimate N−1 adaptation). Score a hit for a correct prediction, and set T to the maximum total hits over A and B. Enumerating all 2^4 original outcome histories gives `Pr_null(T=4) = 1/16 = 0.0625`. Simulating independent fresh outcomes against each original history's fixed A/B forecast arrays and averaging over all 2^4 original histories gives `Pr_fixed_forecasts(T=4) = 15/128 = 0.1171875`. These are different **under the exact fair-outcome null**. Thus a fixed-forecast maximum-statistic distribution is not a general calibrated global null for adaptive WF methods.

**Required resolution (retain exploratory freedom):**
- Keep N1 fixed-forecast replay, R=10,000, family maxima, seed logging, and plots. For any statistic **not proven valid for adaptive forecasts**, label its result `N1_FIXED_FORECAST_REFERENCE` or `APPROX_UNCALIBRATED`; do not call it `N1_CALIBRATED`, an exact global p-value, or an automatic correlation correction.
- Permit `N1_CALIBRATED` for a specifically defined statistic and evaluation protocol only after a proof or independent whole-pipeline adaptive-null test demonstrates appropriate Type-I error control. In a **full recursive simulator**, each replicate feeds its simulated earlier outcomes to later method fits/forecasts; that requires running method code and would be a separate explicitly reviewed design, not something smuggled into the standalone rank reporter. Alternatively, use nonadaptive pre-frozen full-window predictions or a valid analytic/sequential test.
- Extend MRT-16 with an **adaptive multi-method** counterexample and a test of the exact calibration assertion. Validating the one-method exact MR4/MR7/MR8/MR11 tails does not validate a family maximum among adaptive forecasts.
- Correct the statements in §18.4 and PO-1 that N1 necessarily accounts for *all* method-built/adaptive patterns. It can diagnose some, not all, with its current replay method.

This is a claim-of-evidence blocker, **not a ban on reporting N1 numbers**. They should be presented with an accurate interpretation under MRD-21's “mark, never suppress” rule.

## CORRECTIONS

**C1 — Bonferroni is guaranteed only when its constituent p-values are valid and its family is appropriate (§§3.7, 5.2–5.3, 5B).** `min(1,M*p)` controls family-wise error at the stated level regardless of correlation **if** each input p is super-uniform under its null and the family/testing protocol is legitimately fixed. It cannot transform `APPROX_UNCALIBRATED` or `IS_NOT_CALIBRATED` reference tails into calibrated global evidence. A post-hoc family defined from inspected results is not rescued merely by counting the tests in that table; search-log disclosure is necessary but not by itself a programme-wide multiple-search adjustment. Keep and display the arithmetic in all cases, but label it `BONFERRONI_REFERENCE_UNCALIBRATED` (or equivalent) when these prerequisites fail. Reserve “guaranteed” for valid local p-values and defensible comparison-family definition. §18.4 should not say a reported adjustment always supplies a guaranteed global figure.

**C2 — Stage-1 probability capability must be channel-specific (§13 item 3).** The present single `probability_capability` enum admits `NORMALIZED_LABEL_PROBABILITY`, `MARGINAL_INCLUSION_PROBABILITY` **or** `PB_CATEGORICAL`, but a Powerball method can legitimately supply both a main-vector marginal *and* a Powerball categorical vector. Define separate `main_probability_kind` and `powerball_probability_kind` (or an equivalent independently typed capability per channel), with `ABSENT` for Oz Lotto's Powerball channel. Include vector lengths, domains, typed normalization tolerances, provenance and per-channel hashes. No probability capability is inferred from arbitrary scores. This is a contract correction, not an extra method obligation.

**C3 — Specify the correct analysis unit (§§3.4, 3.7, 5B, 6, 10, 13).** `track_id` includes TOP or WORST, but MR5 and MR10/MR10.BOTTOM explicitly apply to the **single full ranking** of a method/variant and MR11 explicitly compares **paired TOP and WORST**. Likewise, MR6 and MR14 can use one shared probability vector, not two independent readout forecasts. Yet the CSV says one row per `(track, sub-measure)` and the family size M counts `(track, sub-measure)` pairs. Specify `analysis_unit = READOUT_TRACK | METHOD_VARIANT_RANKING | TOP_WORST_PAIR` (plus a probability-vector unit where needed), assign each measure unambiguously, and count each distinct hypothesis only once. Do not duplicate method-level values into two apparent independent TOP/WORST tests or double the family size. Clarify handling if one readout is unavailable.

**C4 — MR6's zero probability is a valid (bad) logarithmic forecast, not an evaluation-data defect (§MR6).** As currently written `q_j > 0` and an observed label with `q_j=0` is “infinite”, but the evaluator must not smooth frozen probabilities. Permit `q_j=0` when the vector is otherwise a legitimate normalized probability vector. An observed zero then gives a mathematical score of **negative infinity** (not positive infinity); report it with a typed `ZERO_OBSERVED_PROBABILITY`/`LOG_SCORE_NEG_INFINITY` status and a well-defined bottom placement, rather than silently omitting the track, smoothing after the fact or calling the method's valid zero `MR_NUMERIC_INVALID`. If nonfinite value encoding is prohibited, use a tagged nonnumeric representation in the report schema. Also specify its treatment in an N1 replay/reference.

**C5 — MR14's order-four formula is correct for seven chosen labels; generalise its exhaustive small-sample oracle test (§MR14, MRT-11).** The specified inclusion factor `pi_k=(7)_k/(N)_k` and `E_t=E2/7`, `V_t=E4/49 - E_t^2` are production-specialised for a seven-number draw. MRT-11 also asks for enumeration with subset sizes 3 and 4. To test the same identity on those domains, parameterise the derivation by a draw size `K`: `pi_k=(K)_k/(N)_k`, `E_t=E2/K`, `V_t=E4/K^2-E_t^2`; production uses `K=7`. This avoids a false test failure or a misleading comparison. Guard tiny negative floating residuals in `V_t` with an explicit numerical tolerance, without hiding materially invalid variances.
