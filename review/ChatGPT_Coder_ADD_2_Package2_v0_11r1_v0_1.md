## 2. Non-obvious design choices / review history

1. **N−1 is a complete method-visible boundary.** Setting `.flags.writeable=False` on a slice does not prevent `.base` access to later rows. New numeric view arrays each have their own fresh immutable `bytes` backing, with `int64` integers (floats `float64` where applicable); read-only and base-length invariants matter. Dates are opt-in, with a separate digest/schema. The reader hashes the full master **only for orchestration provenance**; it must neither decode suffix fields nor leak a hash, full-file size or any suffix-derived metadata into `DrawView`.
2. **B1 from v0.11 was a genuine scientific security leak.** `order_evidence.master_sha256` was initially method-visible; Claude correctly BLOCKED it. v0.11-r1 exposes only an outcome-independent INIT record filename and `OPERATOR_DRAWN_ORDER_ASSUMED_OWNER_DECISION` label for ordered and paired views. The r1 mutation regression compares every slot, bytes, plain rows and digest; Claude's independent 96-view altered-suffix oracle passed. Do not regress this while adding metadata or later E_2 contracts.
3. **Legacy E_1 is a tightly bounded exception.** E_1 target Powerball 1577 may be forecast from 1144–1576, but its target outcome is never read/scored. The accepted view SHA begins `d47fbbd6`, forecast SHA begins `7f113087`. The **R2/TIE ratified** synthetic training/tie/forecast SHAs begin `df21871f`, `7ce5ab1b`, `7b43d659` (fixture target 1152); the later standalone-runner synthetic pair `3851fa46`/`8a7f917a` is distinct. No golden is updated to make code pass.
4. **Two games stay distinct.** Powerball has 7 main + separate PB; Oz has 7 main and no PB. Oz supplementaries are not prediction/fit/view/seed inputs (the later MR scoring-only exception concerns the evaluator and does not change v0.11). `OPERATOR_DRAWN_ORDER` means a source-order **assumption**, never proof of physical sequence. `PAIRED_DIAGNOSTIC` cannot count one target twice.
5. **Coordinator safety proof is structural, not a live acceptance claim.** The exact v0.6-to-v0.11 coordinator diff reconstructs byte SHA `bc8380b5f20a704c0f47d5f76eeb86156237142b5639e5b9770b8314db3bb822`; 11 protected ASTs are identical. Polling/queue waits were made human-speed without altering protected three-second kill waits. Three switches remain `False`, empty scientific result allowlist. No-status/no-kill, verified PID+creation time/status/ancestry triple check, durable unresolved-orphan marker and manual clearance remain mandatory. Current real orphan-marker state must be checked on the owner's Windows machine before any later authorised launch.
6. **No scientific promotion.** A PASS-looking synthetic `canonical_result.json` is not automatically a real score. Manifest FAIL/orphan-suspected results remain quarantined, and no method may issue a trusted coordinator receipt. Treat method registration, ranking, IS, E_2-readiness and any allowlist entry as separately gated work.
